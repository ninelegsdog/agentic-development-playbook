# 5. Пример спецификации задачи

Формат ТЗ, по которому сделаны все девять ботов (сокращённый фрагмент):

Полный шаблон — в [`templates/spec.md`](../../templates/spec.md). Ниже — его скелет (11
разделов):

1. Позиционирование (кому, задача, отличие)
2. Метрики успеха (измеримые результаты)
3. Scope (v1 / v1.1 / вне объёма)
4. Сценарии (пошаговые, с ожидаемым результатом)
5. UX-контракт (типы клавиатур, переходы)
6. Данные (схема, UNIQUE на конфликтах)
7. Платежи (провайдер, идемпотентность)
8. Админка (роли, команды, аудит)
9. Инфраструктура (webhook/polling, health, метрики, бэкапы, секреты)
10. Тесты и приёмка (контрактные тесты, критерии готовности)
11. Риски (что сломается и что делать)

Правило именования v1: **v1 = минимум сложности, v1.1 = докрутка.** Один флагманский
проект пишется первым и задаёт шаблон для остальных — иначе девять проектов
разъезжаются по UX и контрактам.
