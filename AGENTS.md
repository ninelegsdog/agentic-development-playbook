# AGENTS.md

> Этот репозиторий сам написан по описанному в нём же процессу — принцип «собака
> съела корм» здесь буквальный.

## Роли

- **Пользователь** = владелец продукта. Решает, что делаем и что публикуем.
- **Агент** = инженер + tech lead. Проактивен: доводит задачу до наблюдаемого
  результата, а не до «файл создан».

## Что это

Документ-визитка: архитектура agent harness, принципы работы с контекстом, шаблоны
`AGENTS.md` и ТЗ, чек-листы ревью AI-кода и секретов, цикл тестирования, формат handoff.
Цель — сделать роль автора проверяемой по публичным репозиториям.

## Обязательные правила

- Строка ≤ 120 символов (для текста — 100, чтобы читалось на мобильном)
- Каждое утверждение о коде или инфраструктуре — **измеримо**; если не проверено,
  помечать явно
- Не завышать метрики: фактическое покрытие указывать фактическое
- Секретов в репозитории нет; в `.env.example` — только имена переменных
- Ссылка на проект ведёт на публичный GitHub, не на локальный путь
- Conventional Commits

## Контракты, которые нельзя вывести из кода

- **Запрещено обещать непредусмотренное.** Формулировки про AI, покрытие и
  гарантии проверяются по фактам, а не по желанию продать.
- **Публичный артефакт должен быть проверяем клиентом.** Инструкция, из которой
  нельзя воспроизвести цикл, не годится.
- **Правки фактов — только вместе с указанием даты измерения.**

## Гейты перед коммитом

- Ссылки в README открываются и ведут туда, куда заявлено
- Нет внутренних имён хостов, IP-адресов и служебных путей в тексте,
  предназначенном для публичного чтения
- Числа в тексте сверены с измерением; устаревшие помечены датой
- `git grep -nE '[0-9]{8,10}:[A-Za-z0-9_-]{35}'` — ни одного совпадения

## Где канон

Репозиторий ведётся на одной определённой машине; копии на других машинах каноном
не являются. Публикация — только с машины, где настроена авторизация GitHub.
Проверка публикации — неаутентифицированный GitHub API, а не локальный `git status`.
